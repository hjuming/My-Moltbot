# 📋 小龍女專案同步使用說明

## 🎯 你的任務

小龍女，你每天會自動執行 GitHub 專案同步任務，這是你的核心工作之一！

---

## 📂 輸出檔案格式

### 1. `research/GITHUB_REPOS.md` - 專案總覽

這是主要的專案清單檔案，格式如下：

```markdown
# 🗂️ GitHub 專案總覽

**更新時間**：2026-02-01 19:17
**專案總數**：46

---

| 專案名稱 | 簡介 | 連結 |
| :--- | :--- | :--- |
| ai-deploy-notebook | 我的 AI 助理學習筆記 | [🔗](https://github.com/hjuming/ai-deploy-notebook) |
| map-wedo | 無描述 | [🔗](https://github.com/hjuming/map-wedo) |
...
```

**重點**：
- ✅ 包含專案名稱
- ✅ 包含簡介（從 GitHub 自動抓取）
- ✅ 包含連結
- ✅ 按字母順序排序

### 2. `research/REPO_CHANGES.md` - 變更報告

當有專案新增或刪除時，會產生這個檔案：

```markdown
# 📋 專案變更報告

**日期**：2026-02-01

## ✅ 新增專案（2）

- **map-wedo**
  - 連結：https://github.com/hjuming/map-wedo
  - 描述：無描述

- **tesseral**
  - 連結：https://github.com/hjuming/tesseral
  - 描述：Open source auth infrastructure for B2B SaaS

## ❌ 移除專案（0）

（無）
```

**重點**：
- ✅ 只在有變更時產生
- ✅ 列出新增的專案（含連結和描述）
- ✅ 列出移除的專案
- ✅ 方便老闆快速了解變化

## 🔧 技術細節

### 執行腳本

- **腳本位置**：`scripts/update_repos_enhanced.sh`
- **執行時間**：每天 09:10（台灣時間）
- **執行方式**：GitHub Actions 自動觸發

### 腳本功能

1. **抓取資料**：使用 GitHub API 獲取所有專案（含描述）
2. **排序**：按專案名稱字母順序排序
3. **比對變更**：與舊版本比對，找出新增/刪除的專案
4. **產生報告**：
   - 更新 `GITHUB_REPOS.md`（主檔案）
   - 產生 `REPO_CHANGES.md`（有變更時）
5. **自動提交**：commit 並 push 到 GitHub

### 環境變數

- `READ_ONLY_PAT`：GitHub Personal Access Token（唯讀權限）

## 📝 注意事項

### ✅ 你要做的

1. **保持格式一致**
   - 表格格式不變
   - Markdown 語法正確
   - 連結可點擊

2. **準確回報變更**
   - 新增專案：列出名稱和連結
   - 移除專案：列出名稱
   - 無變更：明確說明

3. **Telegram 通知要清楚**
   - 有變更時，列出前 3 個新增專案
   - 提供完整變更報告連結
   - 使用 emoji 讓訊息更清楚

### ❌ 不要做的

1. **不要更改檔案格式**
   - 表格結構固定
   - 不要自行添加欄位

2. **不要遺漏資訊**
   - 簡介為空時，寫「無描述」
   - 不要省略任何專案

3. **不要在 Telegram 訊息中貼大量內容**
   - 最多顯示 3 個新增專案
   - 其他的提供連結查看

## 🎯 品質標準

### 好的報告範例 ✅

**Telegram 訊息**：
```
📦 專案變更：
  ✅ 新增 2 個專案
     • [map-wedo](https://github.com/hjuming/map-wedo)
     • [tesseral](https://github.com/hjuming/tesseral)
  
🔗 [查看完整變更](...)
```

**理由**：
- ✅ 清楚說明數量
- ✅ 提供專案名稱和連結
- ✅ 提供完整報告連結

### 不好的報告範例 ❌

**Telegram 訊息**：
```
📦 專案變更：有更新
```

**理由**：
- ❌ 太模糊，不知道更新了什麼
- ❌ 沒有提供連結
- ❌ 老闆無法快速了解
